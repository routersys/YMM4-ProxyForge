# ProxyForge for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-ProxyForge.svg)](https://github.com/routersys/YMM4-ProxyForge/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、編集の間だけ使う解像度の低い動画ファイルを作り、プレビューでは元の動画の代わりにそれを読み込む動画読み込みプラグインです。
大きな動画をタイムラインに置くと、YMM4 に付属する ffmpeg で 10 秒分ずつのチャンクに分けてバックグラウンドで生成し、できたチャンクから順に切り替えます。
動画出力のときは元の動画を読み込むため、出力した動画の画質は変わりません。
生成したファイルは YMM4 のユーザーフォルダーのキャッシュに置き、上限を超えた分は最後に使った日時が古いものから消します。

## 概要

本プラグインは YMM4 の動画読み込みプラグインとして動作します。動画読み込みプラグインの先頭に置くと、YMM4 が動画ファイルを開くたびに最初に呼ばれ、条件に合う動画には元の動画の代わりに、解像度を下げた動画ファイルであるプロキシを返します。条件は、設定の「プロキシを使用する」がオンであること、動画出力の最中でないこと、ファイルの大きさが設定の最小サイズ以上であること、透明を含む動画として除外されていないことです。条件に合わない動画は YMM4 の他の読み込みプラグインがそのまま開きます。

プロキシは、元の動画を YMM4 自身の読み込み処理で 1 フレームずつ描画し、設定の解像度へ縮小してから、YMM4 に付属する ffmpeg で H.264 の mp4 に符号化したものです。動画全体を 10 秒分ずつのチャンクに分けて作り、再生している位置のチャンクから先に生成します。生成が終わったチャンクから順に切り替え、まだ無い区間は元の動画をそのまま読みます。

生成したチャンクと索引は `user/resources/cache/ProxyForge` に置きます。設定は YMM4 の設定として `user/setting/<YMM4 のバージョン>/ProxyForge.ProxyForgeSettings.json` に保存します。

画面の表示は日本語のほか、英語、簡体字と繁体字の中国語、韓国語、スペイン語、アラビア語、インドネシア語に対応します。

## 動作要件

| 項目 | 要件 |
|---|---|
| OS | Windows 10 バージョン 2004（ビルド 19041）以降 / Windows 11（64bit） |
| YukkuriMovieMaker4 | 最新版を推奨 |
| ランタイム | .NET 10.0 |

※ ffmpeg は YMM4 に付属するものを使い、別途インストールする必要はありません。ハードウェアエンコーダーは NVIDIA、Intel、AMD の GPU で使えるものを ffmpeg で確かめてから使い、使えるものが無いときはソフトウェアのエンコーダーで生成します。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-ProxyForge/releases/latest) ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4 が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4 を起動し、設定画面の「動画読み込み」にある「ProxyForge」を開きます。読み込み順が「先頭にありません」と表示されているときは「先頭へ移動」を押してください。先頭にないとプロキシは使われません。
4. 100MB 以上の動画をタイムラインに置くと生成が始まり、進捗のウィンドウが右下に出ます。

1.x のキャッシュと設定は引き継ぎません。プラグインのフォルダーに残る 1.x の `cache` フォルダーと `System.IO.Hashing.dll` は 2.0 では使わないので、消して構いません。

## 主な機能

### 1. プロキシの生成

設定の「プロキシを自動で生成する」がオンのとき、設定の最小サイズ以上の動画を YMM4 が開くと、その動画のプロキシの生成を待ち行列へ入れます。生成は 1 本ずつ順に行い、動画出力の最中は待ちます。

生成の前に元の動画を開き、フレーム数とフレームレートと表示の大きさを調べます。プロキシの解像度は、YMM4 が描画する大きさに設定の倍率を掛けて四捨五入し、幅と高さをそれぞれ偶数に切り下げた値です。ビットレートは、幅と高さとフレームレートの積に 0.07 を掛けた値を基準にして、設定の倍率を掛け、100kbps から 100Mbps の間に収めます。フレームレートは元の動画に合わせます。

チャンクの長さは、設定の秒数にフレームレートを掛けて四捨五入したフレーム数です。生成は、プレビューで最後に要求された位置を含むチャンクから始めて後ろへ進み、末尾まで進んだら先頭へ戻ります。既にあるチャンクは飛ばすため、YMM4 を終了して途中で止まった生成は次回に続きから進みます。

ハードウェアエンコーダーを使う設定のときは、`h264_nvenc`、`h264_qsv`、`h264_amf` の中から、ffmpeg で 1 フレームの試し書きに成功した最初のものを使います。試す順は、512MB 以上のビデオメモリを持つ GPU のベンダーのものが先です。使えるものが無いときと、ハードウェアエンコーダーを使わない設定のときは、ffmpeg のソフトウェアの H.264 エンコーダーを使います。出力は `yuv420p` の BT.709 で、音声は含みません。

フレームの縁 2 ピクセルを除いた範囲に透明なピクセルがある動画は、プロキシにすると見た目が変わるため生成を止め、その動画を除外として覚えます。除外はキャッシュの「すべて削除」で消えます。生成の途中で元の動画のファイルが変わったときは、その動画のプロキシを捨てて失敗にします。失敗した動画は YMM4 を起動し直すか、キャッシュの「すべて削除」を行うまで生成し直しません。

### 2. 再生中の切り替え

プロキシを返した動画では、YMM4 が要求した時刻を含むチャンクがあればそのチャンクを読み、無ければ元の動画を読みます。チャンクの位置と大きさは、元の動画を YMM4 が描画する位置と大きさに合わせるため、他のアイテムとの重なりや配置は変わりません。フレームの番号は元の動画の数え方に合わせます。

次のチャンクは再生に先立ってバックグラウンドで開き、開いておくチャンクは再生中のものとその前後の 1 つずつまでにします。全部のチャンクが揃った動画は元の動画を閉じ、以後はプロキシだけを読みます。開けないチャンクがあったときは索引から外して元の動画を読み、次にその動画を開いたときに生成し直します。

### 3. 動画出力中の扱い

動画出力の最中に YMM4 が動画を開いたときは、本プラグインは何も返さず、YMM4 の他の読み込みプラグインが元の動画を開きます。出力した動画の画質は本プラグインの影響を受けません。

出力の最中かどうかは、YMM4 の「動画出力」と「出力」のウィンドウの表示と終了を Windows のウィンドウのイベントで受け取って判断します。「動画出力」のウィンドウが開いてから「出力」のウィンドウが閉じるまでは出力の準備か最中として扱い、準備の間に動画を開く要求があったときは実際のウィンドウを調べて判断します。コマンドラインの `--encode` で起動した YMM4 では常に出力中として扱い、更新の確認は行わず、進捗のウィンドウも出しません。生成中のプロキシがあるときは、出力が終わるまで次のチャンクへ進みません。

### 4. キャッシュ

チャンクは `user/resources/cache/ProxyForge` の中に、元の動画と倍率の組ごとのフォルダーへ `000000.mp4` のような名前で置きます。索引は同じ場所の `index.json` で、元の動画のパスと大きさと更新日時、倍率、解像度、フレームレート、揃ったチャンクの番号、最後に使った日時などを持ちます。元の動画のパスと大きさと更新日時のどれかが変わると別の動画として扱い、古いプロキシは上限の整理で消えます。

合計の大きさが設定の上限を超えると、最後に使った日時が古い動画のプロキシから消します。最初に使うときに索引とファイルを突き合わせ、索引に無いファイルと、ファイルの無い項目を取り除きます。形式が合わない項目も捨てます。

設定画面のキャッシュの一覧では、動画ごとにファイル名、解像度、倍率、揃ったチャンクの数、大きさ、最後に使った日時を表示し、選んだプロキシの削除、すべての削除、フォルダーを開く操作、一覧の更新ができます。

### 5. 生成の進捗

生成の待ち行列に項目がある間、画面の右下に進捗のウィンドウを出します。動画ごとに、待機中、生成中、完了、中止、失敗の状態と、チャンクごとの生成の状況を帯で表示します。生成が終わったチャンクはその位置が緑になり、生成中のチャンクは進み具合の分だけ緑になります。

「キャンセル」は待ち行列にある生成をすべて止めます。生成が終わったチャンクはそのまま残ります。「閉じる」はウィンドウを隠し、待ち行列が空になるまで出しません。設定の「生成の進捗をウィンドウで表示する」を切ると、ウィンドウを出しません。完了した項目は 2 秒後、中止した項目は 3 秒後、失敗した項目は 10 秒後に一覧から消えます。

## 設定画面

YMM4 の設定画面の「動画読み込み」に「ProxyForge」として表示されます。

| 項目 | 既定値 | 内容 |
|---|---|---|
| 読み込み順 | | 本プラグインが動画読み込みプラグインの先頭にあるかを表示します。先頭にないときは「先頭へ移動」で先頭にできます。 |
| ffmpeg | | YMM4 に付属する ffmpeg が見つかったかを表示します。 |
| 生成中 | | 待ち行列にある項目の数を表示します。 |
| 生成の進捗をウィンドウで表示する | オン | 生成中に進捗のウィンドウを出します。 |
| プロキシを使用する | オン | オフにすると、プロキシを返さず生成もしません。 |
| プロキシを自動で生成する | オン | オフにすると、生成済みのプロキシは使いますが、新しい動画の生成は始めません。 |
| 解像度 | 50% | 元の動画の表示の大きさに対する倍率です。10% から 100% までです。 |
| 対象にする最小サイズ | 100MB | これより小さいファイルはプロキシにしません。1MB から 100000MB までです。 |
| ビットレートの倍率 | 50% | 基準のビットレートに掛ける倍率です。1% から 200% までです。 |
| キーフレームの間隔 | 30 フレーム | プロキシのキーフレームの間隔です。1 フレームから 300 フレームまでです。 |
| チャンクの長さ | 10 秒 | 1 つのチャンクに入れる長さです。1 秒から 120 秒までです。 |
| ハードウェアエンコーダーを使用する | オン | オフにするとソフトウェアのエンコーダーだけを使います。 |
| 上限 | 10GB | キャッシュの合計の大きさの上限です。1GB から 1024GB までです。 |

解像度を変えると、その倍率のプロキシを別に生成します。生成済みのプロキシは倍率ごとに残ります。チャンクの長さを変えると、生成が終わっていない動画は初めから作り直します。

## 制限事項

- 本プラグインが動画読み込みプラグインの先頭にないときは、YMM4 の他のプラグインが先に動画を開くため、プロキシは使われません。
- 透明を含む動画はプロキシにしません。
- 生成が終わっていない区間は元の動画を読むため、生成の最中は再生の位置によって画質が変わります。
- プロキシは音声を含みません。音声は YMM4 が元の動画から読みます。
- 生成中は、元の動画の読み込みと縮小と符号化のために CPU と GPU を使います。

## 注意事項

- 動画出力: 出力の最中は元の動画を読みます。出力の判断は YMM4 の「動画出力」と「出力」のウィンドウの題名に基づくため、YMM4 の更新でウィンドウの題名が変わったときは判断できず、出力にプロキシが使われることがあります。
- キャッシュの場所と大きさ: プロキシは `user/resources/cache/ProxyForge` に置き、既定で 10GB まで使います。上限は設定画面で変えられます。
- 元の動画の変更: 元の動画のパスと大きさと更新日時のどれかが変わると、プロキシを生成し直します。
- 更新の確認: YMM4 を起動してから初めて動画を開くときに一度だけ GitHub のリリースを確認し、新しいものがあればメッセージで知らせます。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4 プロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OS の名前とバージョン、.NET のバージョン、CPU のアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4 の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windows のユーザー名、ユーザーフォルダー、AppData のパス、マシン名、ドメイン名、メールアドレス、IPv4 アドレスです。送信元の IP アドレスは受信側へ渡す手前で取り除いています。

動画ファイルの中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子は YMM4 を起動し直すと別の値になります。

置き換えの対象は上に挙げた文字列だけです。例外のメッセージに動画のパスが含まれる場合、フォルダーの名前とファイルの名前はそのまま残ります。動画を Windows のユーザーフォルダーの外に置いている場合、パスは置き換えを受けずにそのまま残ります。

送信するのは想定していない例外だけです。本プラグインが例外を握り潰す箇所と、YMM4 へ処理を返す境界の両方で報告します。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。YMM4 本体やほかのプラグインで起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 生成の失敗として利用者へ知らせるもの | ffmpeg が見つからない、動画を開けない、透明を含む動画である、元の動画が変更された |
| 更新の確認の通信の失敗 | GitHub へ接続できない |
| キャッシュの読み書きで想定している失敗 | 索引を読めない、ファイルを消せない、チャンクを開けない |

送信できなかった報告は YMM4 のユーザーフォルダーへ退避し、次回の起動時に送り直します。送信も再送も非同期に行うため、起動と生成が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
